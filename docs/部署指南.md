# 航友 · 部署指南（Vercel 前端 + HF Spaces 后端）

> 为什么是两段式部署：本产品后端是**常驻服务**（FastAPI + 本地 torch 嵌入模型 +
> SQLite 持久库 + 后台索引线程）。Vercel 是 Serverless 平台——没有常驻进程、
> 没有持久磁盘、函数体积也装不下 torch。因此：
> **前端（静态站点）→ Vercel；后端（Docker 容器）→ Hugging Face Spaces（免费 16GB 内存）。**
> 这也是答辩时讲“部署架构与技术选型”的现成素材。

```
浏览器 ──HTTPS──▶ Vercel（前端静态资源）
   │                    │
   └──HTTPS(fetch)──▶ HF Space（FastAPI Docker：检索/LLM/SQLite）
```

---

## 第一步：部署后端到 HF Spaces（约 15 分钟，含构建）

1. 注册/登录 [huggingface.co](https://huggingface.co)（可用 GitHub 账号）。
2. 点右上角头像 → **New Space**：
   - Space name：`hangyou-api`（随意，最终地址由此生成）
   - SDK：**Docker** ← 关键，选别的跑不起来
   - 硬件：**CPU basic · 2 vCPU · 16GB · 免费**
   - 可见性：**Public**（Private 需要付费才能被跨域访问）
3. 创建后进入 Space → **Files 标签 → Add file → Upload files**，
   把本仓库 `backend/` 下的以下文件全部拖进去（保持路径结构）：
   - `Dockerfile`、`.dockerignore`、`README.md`（含 Space 配置头）、`requirements.txt`、`run.py`
   - `app/` 整个目录（app/__init__.py、main.py、config.py、db.py、models.py、
     api_schemas.py、api/、core/ 全部文件）
   - **不要上传**：`data/`、`.env`、`tests/`、`build/`
4. 上传后 Space 自动构建（首次约 5-15 分钟：装 CPU torch + 烘焙嵌入模型）。
   构建完成后 Logs 里出现 `Uvicorn running on ... 7860` 即成功。
   也可在浏览器访问 `https://<你的用户名>-hangyou-api.hf.space/api/health`
   验证：应返回 `{"ok": true, ...}`。
5. 配置密钥（Space → **Settings → Variables and secrets**）：

   | 类型 | 名称 | 值 |
   |---|---|---|
   | Secret | `LLM_API_KEY` | 你的 ElexAPI Key（sk-…） |
   | Variable | `LLM_BASE_URL` | `https://elexapi.elex-tech.com/v1` |
   | Variable | `LLM_MODEL` | `glm-5.3` |
   | Variable | `EXTRA_CORS_ORIGINS` | 先留空，等拿到 Vercel 域名后回填（第 2.4 步） |

> 本地 Git 推送方式（可选替代网页上传）：
> `cd backend && git init && git remote add space https://huggingface.co/spaces/<用户名>/hangyou-api && git push space main`（需要先 `huggingface-cli login` 或用 SSH remote）

## 第二步：部署前端到 Vercel（约 5 分钟）

1. 注册/登录 [vercel.com](https://vercel.com)（用 GitHub 账号最顺）。
2. **Add New → Project → Import** 你的 `Real-mini-semester` 仓库。
3. 配置（唯一关键点）：
   - **Root Directory：`frontend`** ← 不改这个会构建失败
   - Framework Preset：Vite（自动识别）
   - Build Command / Output：默认（`npm run build` / `dist`）
   - **Environment Variables → 添加**：
     `VITE_API_BASE_URL` = `https://<你的用户名>-hangyou-api.hf.space/api`
     （注意结尾带 `/api`；你的用户名里的特殊字符 HF 会转成 `-`，以 health 链接实际域名为准）
4. 点 **Deploy**。约 1 分钟后拿到 `https://xxx.vercel.app`。
5. **回到 HF Space Settings**，把 `EXTRA_CORS_ORIGINS` 设为
   `https://xxx.vercel.app`（多个域名逗号分隔），Save（Space 自动重启）。
   > 没有这步：页面能打开，但所有请求报 CORS 错。
6. 打开 Vercel 域名验收：上传资料 → 提问 → 出双层答案。

## 第三步：可选增强

- **持久数据卷**：HF Space Settings → Storage 挂载 `/data`（免费层可用），
  重启不丢学习记录；不挂则每次重启数据清零（演示场景通常可接受）。
- **Space 休眠**：免费 Space 48 小时无人访问会休眠，首次唤醒约 30 秒
  （答辩前提前打开一次即可；也可 UptimeRobot 定时 ping health 接口）。
- **自定义域名**：Vercel Settings → Domains 绑定，CORS 白名单记得加新域名。

## 常见故障排查

| 症状 | 原因 | 解法 |
|---|---|---|
| 前端能开，请求全失败 | CORS 没配 | 检查 Space 的 `EXTRA_CORS_ORIGINS` 是否含 Vercel 域名（含 https、无尾斜杠） |
| `VITE_API_BASE_URL` 不生效 | 构建时才注入 | 在 Vercel 改完环境变量必须 **Redeploy** |
| 问答报"未配置 Key" | Space Secrets 未加/拼错 | Settings 核对 `LLM_API_KEY`；改完自动重启生效 |
| 首次问答等 30 秒+ | Space 冷启动 | 正常，提前 ping `/api/health` 预热 |
| 上传资料失败 | HF 代理对大文件限制 | 单文件建议 < 50MB；书库大书走本地跑 |
